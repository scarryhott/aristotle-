# Closure-native gate-retention run

This finite control compares four admission rules: reciprocal attempt, central
credential, capital price, and receipt-borne price waiver. Its purpose is to
test **which relation makes a choice admissible**, not to model markets and not
to treat the gate as a closed entropy barrier.

The potential-gate interpretation used by the project is now:

```text
choice
  -> gate proposal
  -> independently checkable relation / receipt
  -> truthful continuation | obstruction | OPEN.
```

The gate is therefore a truth-condition interface on a natural choice. It does
not make a choice true by accepting it, and it does not measure closure by how
much uncertainty it removes.

- A price gate reads holding only, so it refuses a poor genuine attempt while
  admitting a wealthy non-genuine one.
- The receipt-borne gate admits the genuine attempt despite price; its access
  invariant is therefore carried by the receipt relation, not by price.
- Under the declared compounding rule, a bounded newcomer remains excluded as
  the top-linked price rises; reciprocal admission continues.
- The twelve fixed paired controls reproduce the registered ordering: price is
  strictly below reciprocal at every row and never exceeds central admission.

These controls do **not** establish that a receipt is true in the world. That
requires the separate Level-1 calibration and Level-2 external-consequence
audits. A gate verdict cannot certify itself.

The `sorting_cost` used in this bounded family is also not the programme's
universal transformation cost. Sorting cost counts the declared work of
screening attempts in this fixture. The stronger cost target belongs to the
relational transformation itself and must eventually be invariant under
language/definition re-expression.

No claim is made about real markets, actual chaos, entropy, or causal economics.
The runtime is a bounded conditional control aligned with the externally
attested NRRF654 model and the canonical truth-condition interpretation in
[`TRUTH_CONDITION_TRANSLATIONAL_CLOSURE.md`](TRUTH_CONDITION_TRANSLATIONAL_CLOSURE.md).
